WHY IT MATTERS

Comments that actually help AI

Most comments tell AI what code does. Poly-Glot writes comments that explain why — the gold signal for smarter AI.

💬 Unlike other AI tools, Poly-Glot adds WHY comments — not just WHAT. That's what actually makes AI smarter.
Copilot, ChatGPT, and Cursor tell you what your code does. Poly-Glot explains why it was written that way — the trade-offs, decisions, and intent behind every line.
❌ What comment (useless to AI) // Loop through users for (const u of users) {...}
✅ Why comment (AI gold) // Skip inactive users early — // reduces downstream DB calls ~60% for (const u of users) {...}
Why comments give AI coding assistants intent, trade-offs, and context — the exact signal needed for better autocomplete, smarter PR reviews, and accurate RAG retrieval.

FAQ

Common questions

Everything we get asked, answered honestly.

Is my code actually private? How does "never touches your servers" work? −
Your code is sent directly from your browser to OpenAI or Anthropic using the API key you provide. The request never routes through our infrastructure — we have no backend that proxies or logs your code. You can verify this by inspecting network requests in your browser's DevTools.
Which AI models does Poly-Glot support? +
Currently we support OpenAI models (GPT-4o, GPT-4o-mini, GPT-3.5-turbo) and Anthropic models (Claude 3.5 Sonnet, Claude 3 Haiku). We recommend GPT-4o or Claude 3.5 Sonnet for best comment quality.
What's the difference between "Doc", "Why", and "Both" modes? +
Doc mode generates formal documentation comments (JSDoc, PyDoc, etc.). Why mode inserts plain-language inline comments explaining the logic and reasoning. Both mode combines the two for maximum coverage.
Can I use Poly-Glot in my CI/CD pipeline? +
Yes — set your API key as POLY_GLOT_KEY environment variable and use the --diff flag to output a patch file. A GitHub Actions example is in the CLI documentation.
What happens to existing comments when I run the generator? +
By default, Poly-Glot skips functions that already have documentation comments. Use --overwrite to regenerate. We always recommend running --dry-run first, and --backup creates .bak copies before modifying files.
