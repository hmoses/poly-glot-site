Poly-Glot MCP Integrations for AI Clients

What Poly-Glot MCP does, its tools, setup documentation and compatible client requirements.

What is Poly-Glot MCP?

Poly-Glot provides a hosted Streamable HTTP Model Context Protocol server with tools for template discovery, prompt building, comparison preparation, BYOM, language and audio processing, and subscription status. Read-only discovery does not start a trial; Send and restricted tools use verified server-side entitlements.

How many MCP tools are available?

The current MCP server code registers 15 tools: seven core tools, four BYOM tools, and four language and audio tools. Discovery depends on client support and permissions; some tool actions require an authenticated trial or Pro account.

Can any AI assistant connect to Poly-Glot MCP?

Not necessarily. A client must support the appropriate MCP transport and authentication or connection configuration. Consult the client-specific setup instructions.

Troubleshooting Poly-Glot MCP connections, authentication and tools

Step-by-step fixes for remote Streamable HTTP connections in ChatGPT, Claude, Cursor, Goose, VS Code, Windsurf and other compatible MCP clients. All clients use the same Poly-Glot server, with 15 tools across templates, comparison, custom models, and languages.

Production MCP URL — use this exact HTTPS address https://br-steep-leaf-ae2o29qz-mcp.compute.c-2.us-east-2.aws.neon.tech/mcp

Start with these four checks

  1. Use the exact server URL. Paste the HTTPS endpoint above, including /mcp; do not paste a Glama, MCP.so or GitHub directory URL.
  2. Choose remote Streamable HTTP. Select the client's remote HTTP MCP option. Poly-Glot is hosted: no npm install, localhost port, or stdio command is required.
  3. Authorize and enable tools. Complete any sign-in or authorization prompt, approve tool permissions, then refresh or rescan the server in your client.
  4. Run a read-only test first. Ask your client to use get_language_options or search_templates; then use get_subscription_status to check trial and Pro availability.

Troubleshooting by MCP client

ChatGPT

Use the Apps or developer/custom MCP configuration available to your account or workspace. Add the remote URL, complete any authorization, scan tools and select the app in your chat. App and developer-mode availability varies by plan and workspace permissions.

Official client help ↗

Claude / Claude Desktop

Add Poly-Glot under Settings → Connectors as a custom remote connector. If it does not appear in chat, enable it in your tools menu. Remote connectors are not configured using the local Claude Desktop stdio JSON file.

Official client help ↗

Cursor

Open your MCP server settings, add a remote Streamable HTTP server using the endpoint above, and enable it. If no tools are listed, refresh the MCP servers, approve permissions and verify the client supports this transport.

Goose

Add Poly-Glot as a remote MCP extension using Streamable HTTP rather than a local command. Enable the extension, restart its session if necessary and test a read-only tool before trying Send or custom-model tools.

VS Code

In an MCP-capable VS Code setup, add the URL as an HTTP remote MCP server, not a local stdio process. Check workspace trust and tool approvals, then refresh the server and confirm tool discovery.

Windsurf and other MCP clients

Confirm your client's version supports remote Streamable HTTP MCP servers. Use the production URL and enable its tools; if your client supports only stdio or legacy SSE, consult its current remote-MCP documentation.

Common MCP errors and fixes

Server unavailable, connection failed or 404

Verify the full https://…/mcp URL and remote HTTP transport. Re-add the connection and try again. A browser GET to an MCP endpoint is not a valid tool test; the client must use the MCP protocol. Check the client network and the server health endpoint; do not mistake a directory listing for the server.

401 Unauthorized or authorization loop

Use the client's account authorization flow and reconnect if the session expires. Check the server's authentication requirements and client permissions. Never paste Apple passwords, API tokens or subscription receipts into public chats, screenshots or issue reports.

403 Forbidden or tool permission denied

Confirm the client granted this connector permission to use the requested tool. Ask the workspace admin about policies if necessary. A 403 may also reflect an authentication or origin-policy restriction—not necessarily an expired subscription.

No tools found, old tool list or tool not recognized

Enable the connector and refresh or rescan tools. The current server documents 15 tools. Outdated directory summaries do not change the live tool registry. Try get_language_options; check that your MCP client can discover remote tools.

Trial expired, Pro required or send limit reached

Use get_subscription_status to inspect current access. The app-managed three-day trial starts on the first qualifying Send; after expiry, free access includes 25 featured templates and one single-AI Send per rolling 24 hours. Compare Mode, BYOM and other Pro features require appropriate access. To resolve a paid-access mismatch, sign in with the linked account and verify or restore your Apple subscription in the app.

429 rate limit, timeout, 500/502/503 or network error

Retry after a short delay and check the client's network, any proxy or firewall, and server status. Avoid repeating a paid or Send action until you have checked whether the previous request completed. Include the time, MCP client and error code in a support request—never include secrets.

Wrong language, translation, transcription or audio error

Use get_language_options to choose a supported language, then verify input and output language settings. For transcribe_audio, confirm the audio format, size and permissions match tool requirements. Try detect_language or translate_text separately to isolate the issue.

Custom model (BYOM) validation or execution fails

First call get_custom_model_capabilities, then validate_custom_model. Use a reachable HTTPS model endpoint, the correct adapter and model identifier, and a valid temporary credential. Check your model provider's API response. Do not share API keys in logs or support messages.
